# Нитка

Локальная сверка отчётов с первичными документами с привязкой результатов к источникам.

Репозиторий предназначен для работы команды на хакатоне.

## Архитектура

- `src/nitka/contracts/` — общие модели входов, извлечения и результатов.
- `src/nitka/extraction/` — чтение документов и ссылки на исходные данные.
- `src/nitka/ocr/` — локальное распознавание сканов.
- `src/nitka/analysis/` — сопоставление и детерминированные правила сверки.
- `frontend/` — пользовательский интерфейс.
- `tests/` — автоматические проверки.
- `examples/` — синтетические примеры.

Входные файлы → извлечение → сопоставление → правила → сохранённый результат. Streamlit вызывает тот же прикладной сценарий, что и библиотечный интерфейс.

## Разработка

Требуется Python 3.12. Из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m mypy
```

Streamlit принимает КФЗ и первичные документы и показывает итог локальной сверки. Настройка профиля, OCR и хранилища описана в [руководстве интерфейса](frontend/README.md). Синтетические комплекты доступны в режиме «Демонстрация».

Реальные документы, персональные данные, секреты, результаты запусков и веса моделей не входят в этот коммит. Каталоги `data/`, `uploads/`, `runs/` и `models/` исключены из Git; перед добавлением файлов необходимо проверять staged diff.

## Параллельная работа

- `frontend` — Mark: `frontend/` и `tests/test_ui_labels.py`.
- `backend-extraction` — Mark: адаптеры `extraction/`, `ocr/`, конфигурация OCR и их тесты.
- `backend-rules` — напарник: `analysis/`, pipeline, исправления, хранение и их тесты.

Общие контракты, `amounts.py`, `extraction/ports.py`, `extraction/loading.py`, `extraction/normalization.py`, общие фикстуры и корневые настройки меняются последовательно через `main` владельцем Mark с согласованием интерфейсов. Зависимости получают слиянием `main`; одни и те же файлы не переносятся независимо в разные ветки. Роли относятся к переносу и дальнейшей работе, исходное авторство сохраняется.

Проверка общей основы: `python -m pytest tests/test_normalization.py tests/test_validation.py`.

## Проверка и запуск

После установки backend-зависимостей установите `pip install -r frontend/requirements.txt`.
Проверки: `python -m pytest`, `python -m ruff check .`, `python -m mypy`.
Демо запускается командой `python examples/demo.py`, локальный интерфейс — `python -m streamlit run frontend/app.py --server.address 127.0.0.1`.
Настройка локального OCR: [config/ocr/README.md](config/ocr/README.md).

## Границы публичного переноса

Приложение перенесено из снимка `ea9fa187fff605f6a1b1fb9ca4411dce109a52b8` приватного проекта. Учебный договор и связанные тесты адаптированы для публичного примера. Синтетические legacy-фикстуры сохраняют исходные байты для проверки совместимости; это не пользовательские документы.

Не включены реальные документы, персональные данные, секреты, веса моделей, результаты запусков, окружения, кэши, локальные инструкции и навыки агентов, исторические планы и аудиты разработки. Они не нужны для работы приложения либо не предназначены для публикации. Корневая документация и настройки адаптированы для публичного репозитория.

Ветки B04/B05 содержат отдельную дальнейшую разработку, отсутствующую в указанном снимке; в этот перенос она не входит.
