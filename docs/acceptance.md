# Приёмка кейса 5

Используйте [профиль кейса 5](../config/case5.json) и рабочий комплект организатора. Исходная КФЗ относится к договору `24/03/15-01`, строке «3 этап, 2026 г.» и периоду январь–май 2026 года. Дельта считается как сумма в КФЗ минус сумма по представленным документам.

## Подготовка

Установите зависимости разработки и интерфейса по [README](../README.md#разработка) и [локальный OCR](../config/ocr/README.md). Подготовьте под `runs/acceptance-inputs/` каталоги `report/` с оригинальной КФЗ `01_*.pdf`, `support/` с 22 документами `02`–`15`, включая `10`, и пустой `technical/`. README организатора и книгу ответов оставьте для сверки ожиданий. Укажите каталог моделей и запустите из корня репозитория, например в PowerShell:

```powershell
$case = (Resolve-Path 'runs/acceptance-inputs').Path
$env:NITKA_PACKAGE_SMOKE_DIR = $case
$env:NITKA_PACKAGE_SMOKE_PROFILE = (Resolve-Path 'config/case5.json').Path
$env:NITKA_OCR_MODELS = (Resolve-Path 'models/ppocr-v5').Path
$env:NITKA_KFZ_SMOKE_PDF = (Get-ChildItem -LiteralPath "$case/report" -Filter '01_*.pdf').FullName
$env:NITKA_PAYROLL_SMOKE_DIR = "$case/support"
$env:NITKA_OCR_SMOKE_IMAGES = (Get-ChildItem -LiteralPath "$case/support" -Filter '12_*.png').FullName
$env:PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK = 'True'
python -m pytest -rs
python -m ruff check .
python -m mypy
```

Проверьте, что тесты с моделью и загрузкой выполнились. Для тестов PDF с синтетическими актами нужен Linux со шрифтами Liberation Sans по путям `/usr/share/fonts/liberation/LiberationSans-Regular.ttf` и `/usr/share/fonts/liberation/LiberationSans-Bold.ttf`. Тест загрузки требует Streamlit с поддержкой `AppTest.file_uploader`.

Тесты изменяют отдельную временную копию DOCX. «Чистая» копия означает, что суммы по выполненным проверкам совпали. Непроверенная детализация по-прежнему требует ручной проверки. Для 0800 и 0900 полнота представленной первички отображается отдельно от совпадения сумм.

В браузерной приёмке 14 ноября 2026 года после перезапуска контейнера открылись обе редакции одного запуска. В скачанных JSON дельта по 0800 и итогу составила +12 500,00 ₽ в первой редакции и 0,00 ₽ во второй. В PDF обеих редакций сохранились сведения об исключениях, адреса источников и отметка о полноте первички. Контрольная сумма скачанного файла 04 совпала с исходной.

## Показ для жюри (4 минуты)

1. Откройте «Свои документы». Покажите профиль, загрузите КФЗ и 22 файла первички, нажмите «Проверить свои файлы». Для перехода к результату при задержке OCR держите ID отдельного запуска исходного комплекта в редакции 1.
2. Покажите 0800 и итог по первичке. Разница +12 500,00 ₽ в двух строках следует из одного расхождения. Сравните её со статусом «Не проверено» в детализации. Первичка покрывает меньшую сумму по 0800, а полнота комплекта по 0800 и 0900 не установлена.
3. В «Доказательствах» выберите 0800 и файл 04. Откройте страницу с выделенной OCR-областью. При необходимости покажите адрес ячейки в 0200 и фрагмент DOCX 06. В таблице исключений покажите дубль 10, другой период 14 и другой договор 15.
4. Для демонстрации перерасчёта выберите DOCX 06 по статье 0800, задайте `282 500,00` и комментарий «Учебная правка для показа перерасчёта». Обе дельты станут нулевыми в редакции 2. Откройте историю правок, затем редакцию 1 с исходными значениями. В рабочем процессе правку обосновывают сверкой с источником.
5. Вернитесь к редакции 2, раскройте «Выгрузить редакцию», скачайте JSON и подготовьте PDF. Покажите в обоих файлах один ID и редакцию 2, в PDF — исключения, адреса источников и историю правки. После перезапуска откройте ту же проверку по её ID.

Для показа без материалов организатора используйте [синтетические комплекты](../frontend/README.md#три-демонстрационных-комплекта). Они позволяют отдельно показать полный результат без расхождений и результат с недостатком данных.
