# Общий профиль проверки

`nitka.contracts.profile.CaseProfile` задаёт договор, период услуги, целевую строку отчёта, коды статей и роли входных файлов. Профиль не является источником денежных сумм и не заменяет исходный текст документа.

`tests/fixtures/case_contract.json` — учебная фикстура с договором `DEMO-CONTRACT-001`. Номера кейсов, даты и конфликты служат тестовыми значениями; это не описание реальных документов. Сценарий намеренно содержит разные номера кейса и несовпадающие годы шапки и выбранного периода, чтобы проверять сохранение исходных наблюдений.

## Контракты

- `Source` сохраняет `raw_text`, нормализованное значение, способ извлечения и адрес источника: ячейку, страницу, OCR bbox или положение в DOCX.
- `ExtractedRow.fields` связывает реквизиты с идентификаторами источников: contract, service_period, document_date, article_code, operation_id, classification_basis, fragment.
- `REPORT` и `SUPPORT` — рабочие роли; `TECHNICAL` и `ORACLE` — технические входы. Эти группы не пересекаются.
- `selects_target_row()` выбирает строку, не изменяя исходный текст, и отвергает строку общего итога.
- `conflicts` и `raw_header_text` сохраняют расхождения между конфигурацией и наблюдениями.
- `AnalysisResult.excluded_documents` описывает дубли, другой договор/период и технические документы отдельно от принятых соответствий.
- Суммы сериализуются строками, вычисления используют Decimal; неизвестное значение не подменяется нулём.

Для сверки используйте `run_pipeline(..., extractor=PackageExtractor(...), matcher=CaseMatcher(profile))`.

Чтобы сохранить проверку, вызовите `nitka.storage.run_and_save` с теми же
экстрактором и сопоставлением. Передайте им один профиль. В хранилище останутся снимки
рабочих файлов, профиль, версия правил и полный результат сопоставления.
В сохранённом извлечении указаны версия экстрактора, настройки OCR и SHA-256
весов по распознанным страницам.

`load_run` и `replay_run` сверяют текущий результат по сохранённому извлечению.
`correct_run_amount` создаёт новую редакцию и повторяет сопоставление по
профилю. Передавайте номер открытой редакции в `expected_revision`. Если её
уже сменили, загрузите актуальную редакцию перед правкой. Для запусков,
созданных прежними версиями правил, доступен опубликованный результат.
Для правки такого запуска выполните новую проверку.
Оба этапа используют один профиль. Результат включает причины исключения, неподтверждённые показатели и ссылки на источники.

- Пакет КФЗ должен содержать один отчёт. Договор из шапки и точная пара «этап, год» должны совпадать с профилем. Период годовой строки — пересечение календарного года строки с месяцами из шапки, включая первый и последний день граничных месяцев. Даты начала и окончания этапа сохраняются как отдельные реквизиты.
- При отсутствии, конфликте или нечитаемости обязательного реквизита результат требует ручной проверки. Денежные проверки получают `NOT_RUN / REPORT_SCOPE_UNVERIFIED`. Исходный OCR-текст, координаты и уверенность остаются доступны.
- Явный месяц услуги имеет приоритет. Нечитаемый или противоречивый период требует проверки.
- Для разовых расходов 0800 и 0900, где период услуги отсутствует, применимость определяется по дате документа и отмечается в результате. Для зарплаты и взносов требуется подтверждение каждого месяца профиля.
- Статья определяется по коду или назначению расхода. Дубли с одной идентичностью и одинаковой суммой учитываются один раз, противоречивые операции требуют проверки.
- Для структурированного OCR-номера договора с уверенностью от 0,95 принимается точное совпадение с профилем. Чужой OCR-номер исключает документ только при повторении номера в тексте назначения. Предупреждения OCR сохраняются.
- Дельта равна сумме КФЗ минус подтверждённая сумма. Общий итог сравнивается с первичкой только при наличии подтверждения для всех требуемых статей. Трудоёмкость и внутренние разбивки отражаются отдельно как непроверенные.
